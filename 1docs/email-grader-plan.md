# 이메일 과제 채점 자동화 아키텍처 개편 및 운영 계획

> **문서 목적**: 사용자의 메인 크롬 환경을 1%도 건드리지 않고, 단일 고정 전용 프로필을 통해 매주 반복 가능한 안정적인 이메일 과제 채점·시트 동기화·자동 답장 체계를 구축한다.

---

## 1. 현황 분석 및 교훈

### 이전 방식의 치명적 문제점
1. **메인 크롬 세션 만료 (로그아웃 재앙)**:
   - 사용자의 메인 크롬(`~/.config/google-chrome`)에서 `Profile 4` 데이터를 임시 폴더로 복사해 실행하는 과정에서 리눅스 OS Keyring(비밀번호 보관소) 쿠키 복호화 불일치 및 Google 보안 서버의 다중 세션 충돌 감지가 발생함.
   - 결과적으로 메인 크롬의 모든 프로필 세션이 강제 만료되어 모든 서비스에서 재로그인 및 2차 인증을 해야 하는 심각한 부작용 발생.
2. **전체 크롬 강제 종료의 비효율**:
   - 디버깅 포트(`9222`)를 열기 위해 `pkill chrome`으로 사용자가 작업 중이던 모든 창을 강제로 닫아야 했음.
3. **매주 일회성 스크립트 작성**:
   - 주차마다 `tmp/run_*.py`를 새로 작성하고 디버깅하여 운영 유지보수 비용이 과도하게 발생함.

---

## 2. 핵심 설계 원칙 (Zero-Collision & Single Profile)

1. **메인 크롬 절대 무간섭 (Zero Interference)**:
   - 사용자의 일상 업무 크롬(`~/.config/google-chrome`)은 파일 하나조차 읽거나 복사하지 않는다.
   - 채점 시 사용자의 크롬 창을 종료할 필요가 전혀 없으며, 사용자가 웹서핑/업무 중이어도 100% 공존한다.
2. **단일 전용 프로필 영구 고정 (No Profile Proliferation)**:
   - 오직 **`~/.config/eval-stu-grader`** 단 하나의 고정 경로만 사용한다.
   - 이 디렉터리 내에는 오직 기본 `Default` 프로필 하나만 존재하며, 새로운 프로필 번호(`Profile 1`, `Profile 2`...)가 무한 증식하지 않는다.
3. **정규 CLI 표준화 (Standardized Tooling)**:
   - 매주 스크립트를 새로 만들지 않고, `./bin/grade-email.py --task 0.x` 단 한 줄로 실행되도록 정규화한다.

## 💡 [쉬운 설명] "왜 기존 기본(0번) 프로필과 전혀 다른가요?"

사용자께서 자주 하시는 질문을 바탕으로 가장 쉽게 풀어쓴 개념 정리입니다:

### Q1. 새 경로의 `Default`는 기존 크롬의 0번 프로필(`Default`)과 같은 건가요?
**A. 이름만 같을 뿐, 실제로는 주소와 집 자체가 완전히 다른 '100% 남남'입니다.**

* **기존 메인 크롬 (아파트)**:
  - 주소: `~/.config/google-chrome`
  - 이 아파트 안에는 0번 방(`Default`), 1번 방, 4번 방(`Profile 4`)이 있습니다.
  - 방 이름은 달라도 **아파트의 현관문(마스터 프로세스)**과 **경비실(암호화 키)**을 공유하기 때문에, 4번 방을 억지로 건드리다 아파트 전체 불이 꺼지고 세션이 로그아웃되는 대형 사고가 났던 것입니다.
* **새 채점 전용 크롬 (독립 단독주택)**:
  - 주소: `~/.config/eval-stu-grader`
  - 아파트 옆 동네에 **아예 완전히 새로운 단독 건물**을 하나 지은 것입니다.
  - 새 건물을 지으면 그 안에도 '기본 거실(`Default`)'이라는 방이 생기지만, **기존 아파트의 0번 방과는 위치도, 열쇠도, 전기(프로세스)도 완전히 다른 별개의 세상**입니다.

### Q2. 프로필 번호가 왜 안 늘어나나요?
* 크롬을 평소에 쓸 때 "새 사용자 추가"를 누르면 메인 아파트 안에 `Profile 1`, `Profile 2`, `Profile 3`... 방이 끝없이 늘어납니다.
* 하지만 자동화 실행 시 `--user-data-dir=~/.config/eval-stu-grader`라고 **지정된 단 하나의 주소만 콕 집어서 실행**하면, 크롬은 항상 그 집의 기본 거실(`Default`) 하나만 열고 닫습니다.
* 따라서 새로운 프로필 번호가 생기거나 늘어날 가능성이 **원천적으로 0%**입니다.

### Q3. 그래서 사용자에게 무엇이 좋아지나요?
1. **내 크롬을 안 꺼도 됩니다**: 평소 쓰시던 유튜브, 업무 메일, 깃허브 창을 켠 채로 채점 프로그램을 돌려도 됩니다.
2. **내 계정이 안 튕깁니다**: 쿠키와 암호화 키를 건드리지 않으므로 로그아웃 사고가 절대 발생하지 않습니다.
3. **매주 안 헤맵니다**: 로그인 딱 1번만 해두면 매주 명령어 한 줄로 30초 만에 채점이 끝납니다.

## 4. 단계별 구축 및 운영 로드맵

### 📌 [Step 1] 전용 프로필 단 1회 초기 설정 (수동 로그인)
- **대상 경로**: `~/.config/eval-stu-grader`
- **수행 절차**:
  1. 독립된 전용 창을 1회 실행:
     ```bash
     google-chrome --user-data-dir=$HOME/.config/eval-stu-grader
     ```
  2. 사용자가 해당 창에서 Gmail(`wonhyukc@stu.ac.kr`) 로그인 및 2차 인증을 완료.
  3. 로그인 완료 후 해당 창을 닫음.
- **결과**: `~/.config/eval-stu-grader/Default`에 독립된 영구 인증 쿠키가 생성되며, 이후 추가 인증이나 창 열기 없이 백그라운드 자동화 가능.

---

### 📌 [Step 2] 범용 정규 CLI 도구 개발 (`bin/grade-email.py`)
- **실행 인터페이스**:
  ```bash
  # 기본 실행 (예: 0.3 과제 채점)
  ./bin/grade-email.py --task 0.3

  # 마감일 수동 지정 필요 시
  ./bin/grade-email.py --task 0.4 --deadline "2026-09-25 00:15"
  ```
- **주요 기능 및 파이프라인**:
  1. **독립 브라우저 기동**: 메인 크롬과 무관하게 `~/.config/eval-stu-grader`로 백그라운드 크롬 기동 (`--remote-debugging-port=9222`).
  2. **메일 수집 및 순회**: Gmail 검색 필터 자동 적용 후 스레드 본문, 발신자, 일시 파싱.
  3. **5단계 티어 채점 (SSOT 준수)**:
     - 1.0(정상) / 0.9(경미오차) / 0.7(형식미흡) / 0.5(지각) / 0.2(지각+형식미흡) / 0.0점(시트 제외).
     - 인용문 제외 순수 본문 30자 이상 검증.
  4. **구글 시트 멱등 Upsert (`modules/sheet_updater.py`)**:
     - E트랙(웹 1/2반): 100% 영문 기록 (`web-stu0926`, gid: 1892167835).
     - K트랙(파이썬 4반): 100% 한글 기록 (`04반 성적부`, gid: 1514293361).
     - 과제 유형 `'0.x` 문자열 포맷팅 및 중복 방지.
  5. **미답장 건 한정 자동 답장**:
     - `wonhyukc@stu.ac.kr`의 답장 이력이 없는 스레드만 선별.
     - 트랙별 언어(영문/한글)로 점수 및 피드백 회신.
  6. **자원 정리**:
     - 채점용 크롬 프로세스만 자동 종료 (`pkill -TERM chrome` 같은 전체 강제 종료 배제).
